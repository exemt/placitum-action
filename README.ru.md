# Placitum action inspector

[English](README.md) · Русский

Инспектор действий рассылает сигналы другим инспекторам и модулю. Он сверяет маршрут и запрос с
профилем и говорит соседям, что делать: смягчить `modsec` на доверенном пути, сообщить капче, что
клиент грузит статику, пропустить служебный запрос, добавить или снять баллы на маршруте
(`do: score`), пометить запись, переопределить журнал и архив. В профиле есть условия — сравнения
значений запроса с наборами и текстом. Правило работает всегда, при выполненном условии или при
невыполненном.

Отвечает он всегда `allow`. Баллы на маршруте двигает сигнал `score`, его исполняет модуль.
Собственный сбой (повреждённое сообщение, чужая версия схемы, перегрузка, паника, буфер не отдал
объект) даёт `verdict: error` с кодом `ACTION_*`, и сбой виден в аудите. Волна при этом доходит до
конца, потому что инспектор пассивный.

Ставьте его на волну раньше получателей: соседи на той же волне его сигналов не видят. Сигналы
уходят только на фазе запроса, на остальных ответ `allow` с `ACTION_IDLE`.

## Профили

Каталог `WAF_ACTION_PROFILES` (по умолчанию `./profiles`), один файл `<имя>.yaml` на профиль.
Имя называет `profile=` на маршруте; имени, которого нет среди загруженных, отвечает
`verdict: error` с `ACTION_UNKNOWN_PROFILE`. Каталог перечитывается на ходу; повреждённая правка не
заменяет живой снимок.

Второй путь — применение из панели: профили держит панель, а применение кладёт манифест в KV
`WAF_DESIRED` под ключом `policy/action`. Инспектор раскладывает поколение в `WAF_ACTION_DATA`
(по умолчанию `<профили>.applied`) плоским каталогом `<имя>.yaml` и переключает загрузчик на него;
повреждённое поколение не применяется, в кадре присутствия виден `apply_failed`.

```yaml
mode: enforce            # печатает контроллер; включён ли инспектор -- решает маршрут
conditions:              # именованные условия; правила ссылаются на них по имени
  - name: trusted_key
    all:                 # строки по И: сошлись все -- условие истинно
      - value: $http_x_api_key     # значение из запроса (запись -- как у if модуля)
        op: in                     # in | not_in -- против набора; eq | ne -- против текста
        dataset: api_keys          # список пространства: динамический (зеркало keeper) или статический (static: true)
      - value: $request_method
        op: eq
        text: POST
  - name: from_office
    any:                 # строки по ИЛИ: сошлась хоть одна -- условие истинно
      - value: $remote_addr
        op: in
        dataset: office_nets
        type: cidr                 # набор адресов: сравнение адресное (печатает контроллер)
      - value: $http_x_forwarded_for
        op: in
        dataset: office_nets
        type: cidr
  - name: risky
    any:
      - cond: trusted_key          # ссылка на другое условие: is -- истинно, is_not -- ложно
        op: is_not
      - cond: from_office
        op: is_not
rules:
  - name: calm-modsec-healthz   # имя живёт в журнале и аудите, на провод не уходит
    match:                       # все заданные блоки обязаны совпасть (И)
      path_prefix: "/healthz"    # префикс пути (без строки запроса)
      suffixes: [".json"]        # суффиксы пути, любой из; без регистра
      static: true               # плюс встроенные расширения статики
      methods: [GET, HEAD]       # пусто -- любой метод
    actions:                     # одно и больше
      - to: modsec               # адресат обязателен у сигналов соседу
        do: threshold            # challenge | threshold | skip | reauth | note | mutate | управляющие
        apply: request           # где выбора нет -- проставится словарём
        delta: -50               # только threshold: проценты −100…+900; минус -- скидка, плюс -- строже
        code: ROUTE_TRUSTED      # [A-Z][A-Z0-9_]*, до 64 байт
  - if: trusted_key              # действия уходят, когда условие истинно
    actions:
      - to: modsec
        do: skip
        code: API_KEY_TRUSTED
  - unless: from_office          # действия уходят, когда условие ложно
    actions:
      - do: score                # баллы на маршруте: исполняет модуль, поля to нет
        apply: request
        value: 30                # со знаком, −100…100, не ноль: минус снимает набранное
        code: OUTSIDE_OFFICE
  - if: risky                    # запись в динамический набор: переживает запрос
    actions:
      - list: blocked            # активный набор пространства; to и do у записи нет
        write: net               # addr | net | net_all | asn; пусто -- addr
        ttl: 1h                  # обязателен, не меньше секунды
        code: ACTION_RISKY       # причина; пусто -- ACTION_LIST
```

Правила накопительные, терминальных нет: срабатывают все совпавшие, действия складываются в
порядке строк, предел количества держит модуль (`waf_actions_max`). Пустой `match` совпадает со
всяким запросом профиля — профиль и так выбран маршрутом; без `if` / `unless` правило работает
всегда. Валидация на загрузке повторяет отбраковку модуля: незнакомый глагол, ось не для глагола,
числа вне диапазона, кривая причина, адресат у баллов или записи, ссылка на необъявленное условие,
`if` и `unless` разом — профиль не грузится.

Действие бывает и записью в динамический набор — `list` + `ttl` (+ `write`, `code`), без `to` и
`do`: субъект уходит в активный набор событием keeper `waf.sets.<набор>.event`, и дальше его режет
локальный слой на узле либо инспектор адреса — до шины. `write` — те же четыре вида, что у всех
отправителей: `addr` — адрес клиента (умолчание), `net` — эффективный анонс, `net_all` — все
анонсы над адресом, включая чужие широкие, `asn` — состав системы целиком. Пакет уходит одним
кадром keeper с одной причиной и сроком (без `code` — `ACTION_LIST`): вся или никак. Анонсы и
состав инспектор спрашивает у справочника сетей по gRPC (`WAF_ACTION_GEO_ADDR`) синхронно, в бюджете
сообщения, и только для строк `net` / `net_all` / `asn`; справочник сетей нужен и молчит — ответ
`verdict: error` с `ACTION_GEO_UNAVAILABLE`, исход выбирает `waf_exception` маршрута, адресные
записи того же запроса при этом уходят. Запись срабатывает на каждом совпавшем запросе и
продлевает срок: памяти «уже записано» у инспектора нет, повторы режут набором перед ним или
условием. Контроллер пускает в запись только активный набор пространства, а под `net` / `net_all`
/ `asn` — только набор адресов.

### Условия

Условие — то же, что `if <значение> in|not in <набор>` у вызова инспектора на маршруте, только
считает его сам инспектор, поэтому сравнивать умеет ещё и с текстом. Строки условия складываются
по И (`all`: сошлись все) либо по ИЛИ (`any`: хоть одна) — ключ ровно один. Строкой бывает и
ссылка на другое условие профиля (`cond: <имя>`, `op: is | is_not` — истинно / ложно): так И
внутри ИЛИ и любая глубина набираются плоскими именованными условиями. Ссылка вперёд законна, на
себя и по кругу — нет: цикл ловится на загрузке, профиль не грузится. Считается лениво: по И — до
первой ложной строки, по ИЛИ — до первой истинной; каждое условие — один раз на запрос, сколько бы
ссылок на него ни было. Семантика совпадения та же, что у модуля: `in` и `eq` истинны, когда
сошлось хоть одно значение; `not_in` и `ne` — когда не сошлось ни одно. Пустое значение — это «не
в наборе», а не отдельный случай: куки нет — значит, её нет и среди доверенных, и `not_in` на ней
истинно. Так же ведёт себя набор, которого зеркало ещё не получило, и объект, которого маршрут не
снимает: отсутствие данных никогда не превращается в совпадение.

В профиле, который раскатывает контроллер, у каждого условия одна строка: И и ИЛИ в панели — это
группы в поле «Когда» правила. Контроллер печатает эти группы отдельными условиями: `rule-N` — «Когда»
правила N целиком, `rule-N.M` — его группа M. Поэтому они видны в `engine.conditions` рядом с
именованными.

| Значение | Откуда | Что даёт |
| --- | --- | --- |
| `$uri`, `$request_uri`, `$host`, `$request_method`, `$scheme`, `$remote_addr` | сообщение | поле как есть; `$request_uri` — путь со строкой запроса из буфера |
| `$http_<имя>`, `$cookie_<имя>`, `$arg_<имя>` | буфер | первое вхождение; имя заголовка — как у nginx (строчные, `-` → `_`), у куки и аргумента — точное |
| `$waf_request_headers.<имя\|*>`, `$waf_request_cookies.<имя\|*>`, `$waf_request_args.<имя\|*>` | буфер | все значения; `*` — все пары объекта |
| `$waf_var.<имя>` | секция `vars` сообщения | поле стандартного набора модуля (`user_agent`, `referer`, `xff`, …) либо `waf_var`; уходит по `vars=` объявления |

Заголовки, куки и аргументы — из копии маршрута (`waf_capture`, по умолчанию `headers args`); за
ними инспектор ходит в буфер лениво, по первому условию, которому они нужны, и один раз на
запрос. Профиль без таких условий буфер не трогает. Маршрут заголовков не копирует —
`$http_<имя>` читается из `vars`, если поле там есть (`user_agent`, `referer`, `x_forwarded_for` →
`xff`, `accept_language`, `origin`, `content_type`, `accept`). Аргументы разбираются как у
селектора модуля: percent-декод, `+` → пробел; куки — trim и снятие кавычек по краям, без декода.
Объект лежал, а взять его не вышло (буфер не ответил, ключа нет) — это сбой инспектора:
`verdict: error`, `ACTION_STORE_ERROR`, исход выбирает `waf_exception` класса inspector.

Список в условии — динамический или статический. Динамический (активный) инспектор держит зеркалом
по проводу keeper (`waf.sets.<набор>`) и заказывает на каждом снимке профилей, чтобы первый запрос не
ждал снапшота. Статический (`static: true`) приходит с поколением: манифест называет его sha256 тела,
инспектор читает тело из внутреннего Redis (`waf.blob.<hex>`), сверяет хеш и кладёт рядом с профилями
(`profiles/.lists/<имя>.txt`, по значению в строке). Профиль, статического списка которого нет, не
грузится. `type: cidr` — список адресов: значение обязано быть адресом, сравнение адресное (точечные
адреса и префиксы); `hash: md5` — список с `hash=md5`: значение хешируется перед поиском. Все три ключа
печатает контроллер из каталога списков; в файле вручную их пишут по определению списка.

Что посчиталось, видно в событии `kind=inspector`: `engine.conditions` — имя → истина/ложь по
условиям, до которых дошло дело, `engine.notes` — где данных не было (`unavailable` — объект или
секция недоступны, `not_ready` — набор ещё не пришёл в зеркало, `not_addr` — значение не читается
адресом).

Напоминание о знаках: `delta` — проценты коэффициента к измерению получателя (множитель
`1 + delta/100`), минус — скидка, плюс — поведение клиента дороже. `value` — проценты шкалы
счётчика получателя, −100…+100: плюс пополняет долей порога срабатывания (+100 — сразу до порога),
минус снимает долю накопленного (−100 — обнулить, ниже нуля не бывает). Применит знак только
получатель, у которого есть правило приёма на отправителя по имени.

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина; список через запятую |
| `REDIS_URL` | `url` из `inspector.conf` | буфер: заголовки и строка запроса для условий. Пусто — условия по ним считают объект недоступным, старт с предупреждением |
| `REDIS_INTERNAL_URL` | `internal` из `inspector.conf` | внутренний Redis: оттуда зеркало наборов берёт пакеты и снапшоты keeper, а статические списки — свои тела. Пусто — берётся буфер, в журнале `internal redis falls back to the exchange`; пусты оба — наборы остаются пустыми |
| `WAF_ACTION_SUBJECT` | `waf.req.action` | подписка |
| `WAF_ACTION_NAME` | `action` | имя в реестре инспекторов |
| `WAF_ACTION_QUEUE` | имя | группа очереди NATS |
| `WAF_ACTION_PROFILES` | `./profiles` | каталог профилей |
| `WAF_ACTION_DATA` | `<профили>.applied` | куда сохраняется применённое поколение |
| `WAF_ACTION_CONF` | `inspector.conf` в рабочем каталоге, затем `/app/inspector.conf` | очередь и адреса Redis |
| `WAF_ACTION_RELOAD_EVERY` | `1s` | как часто проверять каталог профилей |
| `WAF_ACTION_GEO_ADDR` | пусто | справочник сетей по gRPC (`host:port`) для записей с `write: net` / `net_all` / `asn`. Пусто — такие записи отвечают `ACTION_GEO_UNAVAILABLE`, адрес пишется как обычно |
| `WAF_ACTION_GEO_TIMEOUT` | `500ms` | сколько ждать справочник сетей на промахе, в бюджете сообщения |
| `WAF_ACTION_GEO_NEG_MAX` | `0` | предел отрицательного кэша клиента справочника сетей; `0` — умолчание в миллион записей |
| `WAF_ACTION_WORKERS` | число ядер | параллельные воркеры |
| `WAF_ACTION_QUEUE_DEPTH`, `WAF_ACTION_QUEUE_FULL`, `WAF_ACTION_QUEUE_EXPAND` | из `inspector.conf` | переопределения очереди |
| `WAF_ACTION_RESERVE_MS`, `WAF_ACTION_MIN_BUDGET_MS` | `1`, `1` | запас до дедлайна и минимальный бюджет сообщения, мс |
| `WAF_ACTION_VERSIONS` | `2` | версии схемы сообщения, которые процесс принимает; чужая — `verdict: error` с `ACTION_UNSUPPORTED_VERSION` |
| `WAF_ACTION_LOG` | `info` | стартовый уровень журнала: `debug`, `info`, `notice`, `warn`, `error`, `crit`, `alert`; живьём его правит блок `settings` поколения |
| `WAF_HEARTBEAT_EVERY` | `4s` | период кадра присутствия |
| `WAF_LOG_SHIP`, `WAF_LOG_WRITER` | `on`, имя машины | уходит ли журнал процесса на шину и чьим именем подписан |

В образе заданы `NATS_URL=nats://nats:4222`, `WAF_ACTION_PROFILES=/app/profiles` и
`WAF_ACTION_DATA=/var/lib/waf/action`.
