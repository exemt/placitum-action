# Установка

Инспектор не слушает сеть: он подписчик очереди на шине. Ни адреса, ни Service ему не нужно, и
добавление копии не трогает ни узел защиты, ни конфигурацию. Обычно его поднимает фундамент
установки (`placitum-core`).

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | очередь `waf.req.action`, аудит, журнал, поколение профилей |
| Контроллер | да | шлёт профили поколением (раздел `/actions` панели) |
| Redis: обменник | при условиях по заголовкам, кукам, аргументам | снимок запроса по локатору |
| Redis: внутренний | при условиях по наборам | зеркало активных наборов keeper |
| `keeper` | при условиях по наборам и записи исходов | ведёт состав наборов |
| `geo` | при записи в набор с `write: net` / `net_all` / `asn` | анонсы и состав системы по адресу |

Работы у инспектора меньше всех: путь и метод едут в сообщении, и одна копия на контур — обычная
раскладка.

## Переменные

Главные — ниже; полная таблица с умолчаниями в [README.md](README.md#окружение).

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL` | из `inspector.conf` | обменник: объекты запроса для условий |
| `REDIS_INTERNAL_URL` | из `inspector.conf` | внутренний Redis: зеркало наборов. Пусто — берётся обменник с предупреждением в журнале |
| `WAF_ACTION_SUBJECT` | `waf.req.action` | подписка |
| `WAF_ACTION_NAME` | `action` | имя в реестре инспекторов |
| `WAF_ACTION_PROFILES` | `/app/profiles` | профили из образа; поколение кладётся в `WAF_ACTION_DATA` |
| `WAF_ACTION_GEO_ADDR` | пусто | кодер гео (`host:port`). Пусто — записи с `write: net`/`asn` отвечают `ACTION_GEO_UNAVAILABLE` |
| `WAF_ACTION_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |

## Docker Compose

```yaml
services:
  inspector-action:
    image: placitum/action
    environment:
      NATS_URL: nats://nats:4222
      REDIS_URL: redis://redis:6379
      REDIS_INTERNAL_URL: redis://redis-internal:6379
      WAF_ACTION_SUBJECT: waf.req.action
      WAF_ACTION_NAME: action
      WAF_ACTION_GEO_ADDR: geo:50051
    depends_on: [nats, redis, redis-internal]
```

## Место на волне

Действия соседям по своей волне не видны. Инспектор, который должен услышать `action`, обязан
стоять на волне **позже** него — это задаётся на маршруте, а не в профиле. Поставили на одну
волну — просьбы уходят в пустоту, и модуль об этом предупреждает в журнале.

## Проверка после запуска

Своего порта у инспектора нет, и пробы в образе пока нет — проверяют кадр присутствия на шине:

```sh
nats sub 'WAF_STATUS.inspector.action.>' --count 1
```

В журнале при здоровом старте: `profile loaded` по каждому профилю, `object store connected`,
`internal redis` с адресом, `connected` с именем очереди и `desired watch on`.

## Грабли

- **Вердикта, кроме `allow`, у него нет.** Собственный сбой — битое сообщение, чужая версия,
  перегрузка, недоступный обменник — это `verdict: error` с кодом `ACTION_*`, а не тихий `allow`.
  Гейтом инспектор от этого не становится: `error` пассивного волну не срывает.
- **Нет `HEALTHCHECK`.** Контейнер считается здоровым, пока жив процесс. У соседей проба ходит
  сообщением по шине; у отправителя её ещё нет.
- **Условия по заголовкам без обменника** считают объект недоступным — правило с таким условием
  не сработает, и в аудите будет видно почему.
