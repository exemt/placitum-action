# Инспектор действий

Чистый отправитель канала действий (`docs/inspector-actions.md`).
Ничего не проверяет, никого не блокирует и не имеет вердикта кроме `allow`: он смотрит на маршрут
и рассказывает соседям — смягчить `modsec` на доверенном пути, сообщить капче факт про загрузку
статики, попросить пропустить служебный запрос — либо модулю: добавить или снять очки на
маршруте (`do: score`), пометить запись, переопределить журнал и архив. Что именно сказать,
может зависеть от запроса: у профиля есть **условия** — сравнения значений запроса с наборами и
текстом, — и у каждого правила «всегда», «если условие» либо «если не условие».

Отсюда два свойства, которых нет у проверяющих инспекторов:

- **Вердикта, кроме `allow`, у него нет.** Он ничего не проверяет, и вклад в счёт нулевой; очки
  на маршруте он двигает просьбой `score`, которую исполняет модуль. Собственные сбои — битое
  сообщение, чужая версия схемы, перегрузка, паника, обменник, не отдавший объект, — это
  `verdict: error` с машинным кодом (`ACTION_*`): прежний `allow` прятал поломку, ответ выглядел
  годным, и предохранитель считал сыплющийся процесс здоровым. Гейтом инспектор от этого не
  становится: `error` пассивного волну не срывает.
- **Место на волне — раньше получателей.** Действия соседям по своей волне не видны; инспектор,
  который должен услышать `action`, стоит на волне позже него. Действия едут только с фазы
  запроса; на остальных фазах ответ — `allow` без действий (`ACTION_IDLE`).

## Профили

Каталог `WAF_ACTION_PROFILES` (по умолчанию `./profiles`), один файл `<имя>.yaml` на профиль.
Имя называет `profile=` в реестре инспекторов; имени, которого нет среди загруженных, отвечает
`verdict: error` с `ACTION_UNKNOWN_PROFILE` — чужой набор просьб не тише своего, он просто чужой.
Каталог перечитывается на ходу опросом отпечатка; битая правка не заменяет живой снимок.

Второй путь — раскатка контроллером: панель (раздел `/actions`) держит профили в
`action_profiles`, кнопка «Разослать» кладёт манифест в KV `WAF_DESIRED`, ключ
`policy/action` (`docs/inspector-config-distribution.md`).
`internal/desired` раскладывает поколение в `WAF_ACTION_DATA` (по умолчанию
`<профили>.applied`) плоским каталогом `<имя>.yaml` и переключает загрузчик на него;
битое поколение не применяется и виден `apply_failed` в пульсе.

```yaml
mode: enforce            # печатает контроллер; включён ли инспектор -- вызов на маршруте
conditions:              # именованные условия; правила ссылаются на них по имени
  - name: trusted_key
    all:                 # строки по И: сошлись все -- условие истинно
      - value: $http_x_api_key     # значение из запроса (запись -- как у if модуля)
        op: in                     # in | not_in -- против набора; eq | ne -- против текста
        dataset: api_keys          # активный набор пространства (зеркало keeper)
      - value: $request_method
        op: eq
        text: POST
  - name: from_office
    any:                 # строки по ИЛИ: сошлась хоть одна -- условие истинно
      - value: $remote_addr
        op: in
        dataset: office_nets
        type: cidr                 # набор адресов: сравнение адресное (печатает контроллер)
      - value: $http_x_forwarded_for
        op: in
        dataset: office_nets
        type: cidr
  - name: risky
    any:
      - cond: trusted_key          # ссылка на другое условие: is -- истинно, is_not -- ложно
        op: is_not
      - cond: from_office
        op: is_not
rules:
  - name: calm-modsec-healthz   # имя живёт в логе и аудите, на провод не едет
    match:                       # все заданные блоки обязаны совпасть (И)
      path_prefix: "/healthz"    # префикс пути (без строки запроса)
      suffixes: [".json"]        # суффиксы пути, любой из; без регистра
      static: true               # плюс встроенные расширения статики
      methods: [GET, HEAD]       # пусто — любой метод
    actions:                     # одно и больше; форма — docs/inspector-actions.md
      - to: modsec               # адресат обязателен у просьб соседу
        do: threshold            # challenge | threshold | skip | reauth | note | mutate | управляющие
        apply: request           # где выбора нет — проставится словарём
        delta: -50               # только threshold: проценты −100…+900; минус — скидка, плюс — строже
        code: ROUTE_TRUSTED      # [A-Z][A-Z0-9_]*, до 64 байт
  - if: trusted_key              # действия едут, когда условие истинно
    actions:
      - to: modsec
        do: skip
        code: API_KEY_TRUSTED
  - unless: from_office          # действия едут, когда условие ложно
    actions:
      - do: score                # очки на маршруте: исполняет модуль, поля to нет
        apply: request
        value: 30                # со знаком, −100…100, не ноль: минус снимает набранное
        code: OUTSIDE_OFFICE
  - if: risky                    # запись в живой набор: переживает запрос
    actions:
      - list: blocked            # активный набор пространства; to и do у записи нет
        write: net               # addr | net | net_all | asn; пусто -- addr
        ttl: 1h                  # обязателен, не меньше секунды
        code: ACTION_RISKY       # повод; пусто -- ACTION_LIST
```

Правила накопительные, терминальных нет: срабатывают все совпавшие, действия складываются в
порядке строк, предел количества держит модуль (`waf_actions_max`). Пустой `match` совпадает со
всяким запросом профиля — профиль и так выбран маршрутом; без `if` / `unless` правило работает
всегда. Валидация на загрузке повторяет отбраковку модуля: незнакомый глагол, ось не для
глагола, числа вне диапазона, кривой повод, адресат у очков или записи, ссылка на
необъявленное условие, `if` и `unless` разом — профиль не грузится.

Действие бывает и **записью в живой набор** — `list` + `ttl` (+ `write`, `code`), без `to` и
`do`: субъект уезжает в активный набор событием keeper `waf.sets.<набор>.event`, и дальше его режет
локальный слой на краю либо инспектор адреса — до шины. `write` — те же четыре вида, что у всех
отправителей ([modsec](https://github.com/exemt/placitum-modsec/blob/develop/docs/README.md#кого-писать-адрес-подсеть-автономная-система)):
`addr` — адрес клиента (умолчание), `net` — эффективный анонс, `net_all` — все анонсы над адресом,
включая чужие широкие, `asn` — состав системы целиком. Пачка уходит одним кадром keeper с одним
сроком и поводом (без `code` — `ACTION_LIST`): вся или никак. Анонсы и состав инспектор спрашивает у
кодера гео по gRPC (`WAF_ACTION_GEO_ADDR`) синхронно, в бюджете сообщения, и только для строк
`net` / `net_all` / `asn`; кодер нужен и молчит — ответ `verdict: error` с `ACTION_GEO_UNAVAILABLE`,
исход выбирает `waf_exception` маршрута, адресные записи того же запроса при этом уезжают. Запись
срабатывает на каждом совпавшем запросе и продлевает срок: памяти «уже записано» у инспектора нет,
повторы режут набором перед ним или условием. Контроллер пускает в запись только активный набор
пространства, а под `net` / `net_all` / `asn` — только набор адресов.

### Условия

Условие — то же, что `if <значение> in|not in <набор>` у вызова инспектора на маршруте
(`docs/directives/module-copy/list/select.md`), только считает его сам инспектор,
поэтому сравнивать умеет ещё и с текстом. Строки условия складываются по И (`all`: сошлись все)
либо по ИЛИ (`any`: хоть одна) — ключ ровно один. Строкой бывает и ссылка на другое условие
профиля (`cond: <имя>`, `op: is | is_not` — истинно / ложно): так И внутри ИЛИ и любая глубина
набираются плоскими именованными условиями. Ссылка вперёд законна, на себя и по кругу — нет:
цикл ловится на загрузке, профиль не грузится. Считается лениво: по И — до первой ложной строки,
по ИЛИ — до первой истинной; каждое условие — один раз на запрос, сколько бы ссылок на него ни
было. Семантика совпадения та же, что у модуля: `in` и `eq` истинны, когда
сошлось хоть одно значение; `not_in` и `ne` — когда не сошлось ни одно. Пустое значение — это «не в
наборе», а не отдельный случай: куки нет — значит, её нет и среди доверенных, и `not_in` на ней
истинно. Так же ведёт себя набор, которого зеркало ещё не получило, и объект, которого маршрут
не снимает: отсутствие данных никогда не превращается в совпадение.

| Значение | Откуда | Что даёт |
| --- | --- | --- |
| `$uri`, `$request_uri`, `$host`, `$request_method`, `$scheme`, `$remote_addr` | сообщение | поле как есть; `$request_uri` — путь со строкой запроса из обменника |
| `$http_<имя>`, `$cookie_<имя>`, `$arg_<имя>` | обменник | первое вхождение; имя заголовка — как у nginx (строчные, `-` → `_`), у куки и аргумента — точное |
| `$waf_request_headers.<имя\|*>`, `$waf_request_cookies.<имя\|*>`, `$waf_request_args.<имя\|*>` | обменник | все значения; `*` — все пары объекта |
| `$waf_var.<имя>` | секция `vars` сообщения | поле стандартного набора модуля (`user_agent`, `referer`, `xff`, …) либо `waf_var`; едет по `vars=` объявления |

Заголовки, куки и аргументы — из снимка маршрута (`waf_capture`, по умолчанию `headers args`);
за ними инспектор ходит в обменник лениво, по первому условию, которому они нужны, и один раз
на запрос. Профиль без таких условий обменник не трогает. Маршрут заголовков не снимает —
`$http_<имя>` читается из `vars`, если поле там есть (`user_agent`, `referer`,
`x_forwarded_for` → `xff`, `accept_language`, `origin`, `content_type`, `accept`). Аргументы
разбираются как у селектора модуля: percent-декод, `+` → пробел; куки — trim и снятие кавычек по
краям, без декода. Объект лежал, а взять его не вышло (обменник не ответил, ключа нет) — это
сбой инспектора: `verdict: error`, `ACTION_STORE_ERROR`, исход выбирает `waf_exception` класса
inspector.

Наборы — только **активные** списки пространства: инспектор держит их зеркало по проводу keeper
(`waf.sets.<набор>`, [docs/keeper.md](https://github.com/exemt/placitum-keeper/blob/develop/docs/spec.md)) и заказывает на каждом снимке
профилей, чтобы первый запрос не ждал снапшота. `type: cidr` — набор адресов: значение обязано
быть адресом, сравнение адресное (точечные адреса и префиксы); `hash: md5` — набор с
`hash=md5`: значение хешируется перед поиском. Оба ключа печатает контроллер из каталога
наборов; в файле руками их пишут по определению набора.

Что посчиталось, видно в событии `kind=inspector`: `engine.conditions` — имя → истина/ложь по
условиям, до которых дошло дело, `engine.notes` — где данных не было (`unavailable` — объект
или секция недоступны, `not_ready` — набор ещё не приехал в зеркало, `not_addr` — значение не
читается адресом).

Напоминание о знаках: `delta` — проценты коэффициента к измерению получателя (множитель
`1 + delta/100`), минус — скидка, плюс — поведение клиента дороже. `value` — проценты шкалы
счётчика получателя, −100…+100: плюс пополняет долей порога срабатывания (+100 — сразу до
порога), минус снимает долю накопленного (−100 — обнулить, ниже нуля не бывает). Применит знак
только получатель, у которого есть правило приёма на отправителя по имени.

## Окружение

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL` | пусто | обменник объектов: заголовки и строка запроса для условий. Пусто — условия по ним считают объект недоступным, старт с предупреждением |
| `REDIS_INTERNAL_URL` | пусто | внутренний Redis контура: оттуда зеркало наборов берёт пакеты и снапшоты keeper для условий `in` / `not_in`. Пусто — берётся адрес обменника, в журнале `internal redis falls back to the exchange`; пусты оба — наборы остаются пустыми (`packages cannot be read: no internal redis`) |
| `WAF_ACTION_SUBJECT` | `waf.req.action` | подписка |
| `WAF_ACTION_NAME` | `action` | имя в реестре |
| `WAF_ACTION_PROFILES` | `./profiles` | каталог профилей |
| `WAF_ACTION_DATA` | `<профили>.applied` | куда раскатка кладёт применённое поколение |
| `WAF_ACTION_RELOAD_EVERY` | `1s` | опрос отпечатка каталога |
| `WAF_ACTION_GEO_ADDR` | пусто | кодер гео по gRPC (`host:port`, на стенде `geo:50051`) для записей в наборы с `write: net` / `net_all` / `asn`. Пусто — такие записи отвечают `error` (`ACTION_GEO_UNAVAILABLE`), адрес пишется как обычно |
| `WAF_ACTION_GEO_TIMEOUT` | `500ms` | сколько ждать кодер на промахе, в бюджете сообщения; сам ответ стоит доли миллисекунды, бюджет — на дурную минуту сети ([замер](https://github.com/exemt/placitum-geo/blob/develop/docs/README.md)) |
| `WAF_ACTION_GEO_NEG_MAX` | `0` | потолок отрицательного кэша кодера; `0` — умолчание (миллион записей) |
| `WAF_ACTION_WORKERS`, `WAF_ACTION_QUEUE_DEPTH`, `WAF_ACTION_CONF` | | очередь, как у остальных |
| `WAF_ACTION_VERSIONS` | `2` | версии схемы сообщения, которые процесс принимает; чужая — `verdict: error` с `ACTION_UNSUPPORTED_VERSION` |
| `WAF_ACTION_LOG` | `info` | стартовый уровень журнала: `debug`, `info`, `notice`, `warn`, `error`, `crit`, `alert`. Живьём его правит каталог инспекторов — блок `settings` поколения перебивает переменную без рестарта (`docs/inspector-config-distribution.md`) |
| `WAF_LOG_SHIP`, `WAF_HEARTBEAT_EVERY` | | доставка журнала и пульс, как у остальных |

Путь и метод едут в сообщении инлайном; обменник нужен только условиям по заголовкам, кукам и
аргументам, и трогает его только профиль с такими условиями.

## Сборка и поставка

Каталог самодостаточен: ни сборка, ни образ не берут ни одного файла выше по дереву. Поэтому
образ собирается и из рабочего каталога, и из поставочной ветки `deliver/action`, где этот
каталог лежит в корне — `docs/delivery.md`.

```sh
docker build -f deploy/Dockerfile -t waf-action .
```

Сборка прогоняет `go test ./...` и кладёт версию с ревизией в метки OCI
(`--build-arg VERSION=`, `--build-arg REVISION=`). Из профилей в образ едет один `default` —
тот, что поставка не даёт удалить: с ним ходит проба здоровья. Остальные профили привозит
поколение контроллера. Стендовых профилей в репозитории нет вовсе: при сборке прямо из
git-адреса BuildKit `.dockerignore` не применяет, и исключённое им всё равно попало бы в образ.

Что нужно рядом, переменные и проверка после запуска — [INSTALL.md](INSTALL.md); устройство
инспектора — [docs/README.md](docs/README.md).

## Ветки

`develop` — то, что разрабатывается: сюда приезжает каждая выкладка. `main` — выкаченные сборки.
Правок в этом репозитории не делают: обе ветки производные от платформы.
